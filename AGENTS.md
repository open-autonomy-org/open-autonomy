# Open Autonomy — rules for the agent working this repository

- **What this is.** Open Autonomy in four pieces: the platform (`apps/platform`, the Cloudflare Worker that holds each project's funds, meters every spend, takes money in, carries the development stream and serves the site), the starter kits (`packages/kit-hermes`, with `packages/sdk`), the cookbooks (`cookbooks/`), and this install's own boilerplate (`world/`, `hermes/`, which is you). `CONSTITUTION.md` is why. `ROADMAP.md` is the sourced planning memory, maintained by the PM scrum; the kanban holds fleet execution; `CONSTITUTION.md` is what it is and must remain; `CONTRIBUTING.md` is how code is written here.
- **Every spend is on the books.** Never add a way to spend a project's funds that the platform does not meter and publish.
- **Checks.** `bun run check` from the repository root runs every package's tests and typecheck, the kit's check on the cookbook, and the cookbook's own check. It must pass before every push.
- **The world.** `world/` is the product on your machine with no keys: twins of GitHub, Discord and the model gateway, the real worker built from your tree, the kit on a cookbook (`world/README.md`). `WORLD_STATE_ROOT=/opt/data/world bun world/run.ts up` runs it inside your container (the twins are packages in node_modules; the world's own agent takes the valve ports 18787/18788, beside yours), `env -- <cmd>` reaches it, `hermes kanban list` and `hermes cron run pm` drive its agent, `down --purge` forgets it. Verify acceptance there; you cannot reach production. You are that world's operator, never a second agent inside it.
- **Deploy.** You cannot deploy and must not try. The worker deploys through GitHub (`apps/platform/DEPLOY.md`) after a maintainer's review. Prove the change in the world instead; when an acceptance line truly needs the deployed worker, land the code, say so in your report, and leave the item `active`.
- **Git.** You cannot push to `main` and must not try. Work on `agent/<task id>` off a fresh `origin/main`, commit small, and push the branch; the landing workflow opens the pull request and it merges itself when the checks pass. Never rewrite history, never force-push.
- **Secrets.** There are none for you to use: your model calls and your pushes are authorized outside your reach. Never read or print `.env` files or key material; your sessions are published live.
- **Do not edit** `LICENSE`, `SECURITY.md`, `.github/workflows/`, `container/`, `.open-autonomy/reporter.ts`, or anything under `hermes/` except a skill the roadmap asks you to improve; `hermes/` comes from the kit (`create-open-autonomy upgrade .`).
- **Cost.** Your calls are metered and public. Read before writing; run the checks once; stop when verified.
