# lexicon — rules for the agent working this repository

- **What this is.** A shared glossary (`lexicon.json`) with a CLI (`src/lexicon.ts`) that adds, lists and renders it to the homepage (`docs/index.html`, GitHub Pages from `main`), with an Open Autonomy agent (`hermes/`, applied from the template) that also keeps the project's community desk. `CONSTITUTION.md` is what it is and must remain; the board is what you build next, in order; `CONTRIBUTING.md` is how code is written here.
- **Checks.** `bun run check` from the repository root runs the tests; the project has no dependencies to install. It must pass before every push.
- **Verify.** This project has no live surface. An acceptance line is verified by running the command yourself with `bun run lexicon …` and reading its output, and by reading `docs/index.html` after `bun run lexicon render`. State is one JSON file at `$LEXICON_FILE` (default `./lexicon.json`); tests use a temp file.
- **The community.** `.open-autonomy/community.ts` is your door to the repository's issues and discussions, through the API the environment names (`GITHUB_API_URL` and `GITHUB_TOKEN`: in the stack, the valve's GitHub port and the word `valve` — the project's own GitHub App answers). Discord is the project's own application and bot; Hermes uses its native tools to communicate through that identity. The kit's `community` skill (`hermes/skills/open-autonomy/community/`) says what to answer, what to file and what to decline; its job runs every quarter hour.
- **Git.** You cannot push to `main`. Work on `agent/<task id>` off a fresh `origin/main`, commit small with the task id first in the subject, push the branch; it lands through the project's landing rule when the checks pass.
- **Secrets.** The bot tokens can only post as the bot. Never read or print `.env` files or key material; your session is published live.
- **Do not edit** `LICENSE`, `.github/workflows/`, `container/`, `.open-autonomy/reporter.ts`, or anything under `hermes/` except a skill a task asks you to improve.
