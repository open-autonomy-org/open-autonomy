# Changelog

## Unreleased
- **Self-hosting.** `apps/self-host` is the backend deployed bare: one worker file, a `wrangler.toml`, the secrets it needs and the access policy it expects, for a private deployment or a public one without patronage. The backend serves an index of a deployment's projects at `/`, reads private repositories when the deployment allows it (`ALLOW_PRIVATE_REPOSITORIES`), and publishes to npm as `@open-autonomy/backend` beside the SDK and the kit.
- **The backend and the platform, apart.** `packages/backend` is the core one Worker mounts: the books, the keys, the rails, the stream, the timeline and a project's page, with an app around it and one Durable Object whose operations an app extends by name; what an app keeps on the books is persisted beside the core's keys and never read or dropped by it. `apps/platform` is Open Autonomy's app on it: patronage, explore, the giving page, the GitHub login. A private deployment mounts the backend bare. Same worker, same storage, no migration.
- **The timeline: past, present and future in one language.** The platform holds one document of a project's work with a tense, times, a release, an actor and a proof on every item, rendered as read-only views (a board by tense, a sortable list, the timeline by month, the past by release). The Hermes kit's reporter unifies its three homes into it: `CHANGELOG.md` as the past, the board and its sessions as the present, `ROADMAP.md` as the future. The shipped document, the changelog panel and the unused `ROADMAP.yml` codec are gone; the wire's schema is `open-autonomy.timeline.v1`.
- Local subscription setup preserves an installed Codex choice without copying OAuth material, but activation now fails closed: startup refuses the flag or either profile's native selection until a host sidecar and container executor isolate the fleet from operator files and credentials. Funded-model and legacy proxy fleets retain their existing paths.
- Protected-main setup now prepares repository claims and owner policy without committing, switching branches or pushing unrelated work, resumes landed or pending policy safely from stale checkouts, and refuses non-`main` repositories and linked credential files before mutation. Restart recovery also fails closed when committed Hermes configuration cannot be fetched or extracted, preserving an interrupted checkout instead of loading its dirty configuration.
- Setup now verifies real development connections through a standalone protected valve before starting Hermes, explicitly offers a verified subscription alongside the platform's live model catalog, and keeps the chosen provider, model-bound key and usable funding aligned. Container operation permits the valve to persist refreshed subscription tokens while refusing startup unless the agent UID is isolated from credential storage; generated landing workflows arm native auto-merge so delayed required reviews can complete without an unattended retry loop.
- Guided setup now keeps initial fleet connections separate from later application activation: production and sponsorship require an explicit selection, Discord follows the owner's communication choice rather than discovered credentials, and unsupported publication targets fail before mutation. It begins with read-only orientation over the supplied conversation and existing project state, distinguishes agreed, verified, recorded and missing facts, resumes at the first unresolved step, and presents stage changes, results and human handoffs in compact ASCII cards under a static Open Autonomy mark without adding wizard machinery. Its upgrade-managed guide covers project intent, operating defaults, browser-guided credentials, local-world verification and PM handoff. Resumed setup also revalidates the checkout root, origin fetch and push targets, current GitHub identity, repository access and fetch instead of trusting a saved completion marker. An owner-side loopback receiver now saves provider credentials outside Git without exposing them to the agent, including a GitHub App manifest exchange; displayed API keys and bot tokens can move directly from one exact, visible browser field into that protected storage without entering agent output, and setup verifies the saved credential against the expected provider resource before leaving the one-time page. The runtime valve discovers a missing GitHub App installation ID when the credential is used, while setup separately verifies an actual repository read. Owner-rule preparation preserves staged work and existing rulesets, waits for the intended `CODEOWNERS` file to land, and Discord setup verifies the selected destination without rewriting native access or delivery policy.
- New-project setup now follows GitHub's organization/repository structure: it verifies the organization before provisioning, refuses personal or unavailable organization targets without mutation, and discovers established organization communication spaces for project-scoped reuse without sharing credentials, funds or authority.
- Resumed setup now stops before mutation when completed credential files are missing or its saved deploy key is no longer registered with write access; fleet startup likewise requires the developer credential even when a treasurer credential exists.
- Setup now completes the product agreement, verified roster, communication policy, operating configuration, required development connections and startup verification before Hermes begins; PM starts product planning from that established project rather than treating setup's connection record as a brief or backlog. Handoff keeps durable product decisions and source references in the constitution, distinguishes customer data folders from the fleet checkout, and avoids temporary rehearsal or handoff documents. The production guide gives packages and local applications a candidate-specific artifact review, human publication and post-publication verification path without requiring a hosted service.
- Credential storage hardening preserves setup's default external directory, rejects Git- or project-bound destinations and symlink aliases before setup state or key issuance, and prepares the selected parent and regular file with owner-only permissions; the key tool no longer creates the wrong default directory when `--out` points elsewhere.
- Platform key rotation atomically replaces one of three independent credential slots, retains at most one bounded predecessor during grace, refuses rotation forks and revocation races, and continues to reject a fourth independent key.
- SDK 2.4.1 keeps subscription-backed reasoning streams open through quiet intervals by giving the Codex proxy the same finite 255-second idle timeout as the funded-model proxy, replacing Bun's 10-second default that truncated a reproduced 20-second stream.
- **Kit 2.8.2: sourced scrum, release planning and reproducible bootstrap.** PM exhaustively reconciles paginated Git, sessions, community and board evidence into distilled `ROADMAP.md`/`CHANGELOG.md`, keeps bounded source gaps, plans a fixed candidate and version before requesting mandatory human release review, and withdraws stale proposals without treating them as complete. Fresh projects declare Bun 1.3.10 and pin TypeScript 5.9.3 locally; setup verifies the actual service runtime, installs locked dependencies and runs the project check instead of accidentally relying on a global compiler. Runtime identities are validated as container-compatible lowercase slugs before scaffolding or setup mutates provider state, while display names remain separate branding.
- **Kit 2.8.0: the roadmap becomes shared planning memory.** Notable intentions, dependencies and accepted commitments live in a sourced roadmap while native kanban remains fleet working memory; outside contributors need no handoff or planning edit for PM to discover their work.
- Project communication now uses the project-owned `project-communications` skill, Hermes's native messaging and existing GitHub conversations instead of generated routing policy and a custom reminder hook. Public participation is separate from authority: owner direction and release approval are bound to verified platform identities and scoped delegation, confidential channels and DMs stay outside public session discovery, and setup records identities and native permissions before fleet activation. Scheduled coordination receives scoped native Discord history tools, and the GitHub App door can expose read-only PR, check, workflow and release evidence without granting release mutations. This repository uses Discord `#development` for coordination and release review.
- A repository-owned team roster is the shared authority record for the platform, setup and Hermes. The public Team page lets a verified current owner prepare a draft roster PR while rejecting stale, duplicate, malformed or last-owner-removal changes; native operator permissions and release gates remain separate setup checks.
- Setup prepares one reusable project identity bundle—a name, short description and square icon—for GitHub and Discord integrations, preserves existing application IDs across branding or runtime changes, and records the installed project GitHub App without exposing its credentials.
- Kit 2.7.1: shipping requests follow main through board comments and refreshed owner issues without re-blocking a task; pending kit upgrades that change workflows create one owner-review request naming the pull request.
- Kit 2.7.0: human blocks reach the owner through Discord or one assigned GitHub issue, with PM reminders and cleanup on release. The PM tracks landed work awaiting deployment, takes kit upgrades in an idle worktree, and requests a drained restart of the complete stack. SDK 2.4.1 lets the GitHub valve close the project's issues and lets the PM read public deployment status.
- A signed-in `/give` page lets a GitHub user see grant credits and gifts, select a project and earmark, and make an idempotent gift; an org admin can pass Sponsors funds from the grants pool through the same books.
- Project pages compare the commit reported by a configured live service with repository head, link the comparison, and distinguish up-to-date, ahead, divergent and unreachable states.

## Released through deploy-v2026.09.06.4 and create-open-autonomy 2.6.0 — 2026-09-06

- The funding hard-stop stands above the envelopes: a reserve is refused when settled spend plus reservations would exceed the balance the totals say, whatever the envelopes add up to, and a call that cost more than it reserved draws the overage from whatever envelope still holds money.
- **Kit 2.6.0: the guided setup.** `create-open-autonomy setup` reads a project's situation and recommends the doors that fit it — a gated production door, the agent's GitHub App by manifest flow, a Discord channel, the owner's subscription — does every step an API allows, and opens the exact page for the clicks only a person may make. A declined door leaves no trace: the template's schedule no longer presumes a Discord channel, the desk speaks of a channel only when the project has one, and the start script takes the channels from `channels.env` beside the keys.
- **GitHub Sponsors funds the grants pool.** GitHub gives an org one listing, so a sponsorship cannot name a project; it now lands on the org's grants account and is given on to projects from there, and every project page but the pool's own says so on its button.
- Kit 2.5.1: a worker never completes, reclaims, unblocks or archives a task — one completed its own from the shell and skipped the review lane; the handoff is the only way a task ends.
- **Kit 2.5.0: how a project ships.** `.open-autonomy/PRODUCTION.md` is the production door every kit project gets: the agent lands, the owner's `CODEOWNERS` line guards the workflows, and production runs only from a human-cut `deploy-v*` tag through a reviewed environment whose secret no machine holds. The worker pushes once, at the handoff — a push mid-task landed half a feature — and the default turn budget is 160.
- Kit 2.4.10: the container is the stated default for a real deployment; bare is for development and fast debugging. - Kit 2.4.9: a conversation's shell starts in the checkout — a question in the channel is answered from the project's files, not the agent's home.
- Kit 2.4.8: the desk's report is `[SILENT]` or one paragraph, never a harness marker, and its tool has one path.
- Kit 2.4.7: the desk's quarter hour reads GitHub alone — the channel is answered as messages arrive — and a look is four commands, never a search of the home for messages; a doorless desk ends at once.
- Kit 2.4.6: a start syncs the home from origin/main's hermes/ even when the checkout is dirty with a killed attempt's work, so what the agent is never waits on a worker's tree.

- Kit 2.4.4: a desk without a GitHub door is quiet, not blocked, and a worker never ends a task without handing it off for review.
